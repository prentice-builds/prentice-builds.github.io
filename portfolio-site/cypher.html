Cypher

Cypher is my personal AI chief of staff. I use it to think through decisions and to get work done. It is not software. It is a general AI assistant set up with three documents, so that every conversation starts knowing who I am, how I want to work, and where things stand.

I run it across my career and my personal goals. Each one has its own project and its own record of where things stand. This portfolio was built in it.

Context

Who I am, what I am working toward, and the constraints I work inside. Written once and revised rarely.

Rules

How it should behave. When to ask questions and when to just do the task, how to push back, how to write in my voice, and what to flag before I act.

State

Decisions made, work in progress, and what is finished. It records the state of play and not a transcript, and it changes only when something does.

Conversations

One for each piece of work. Because the state lives in a document and not in a chat, a new conversation picks up where the last one stopped.

Three things it does

It holds me to criteria I set in advance

Big decisions get judged against the same short list every time, and I wrote that list when I was not in the middle of one. It also knows my patterns. When I am researching instead of acting, or designing instead of shipping, it says so.

It changes how it works to fit the question

A strategic question gets questions back before it gets an answer. A task gets done. Brainstorming happens only when I ask for it.

It guards the lines I told it to guard

Before anything of mine goes public, it checks the work against my constraints. While this portfolio was being built, it caught a test document that named real companies and stopped it before it was published.

One weekend of it in use

The portfolio you are reading took a weekend. These three moments are from that weekend.

It told me when to stop

I asked what else could be added to a calculator that was already working. It made one addition, listed what it had considered and rejected, and said that anything further was polish.

It caught something I had missed

One of my test documents listed real companies as vendors. My own rule is invented names only. It found them, said so, and replaced them before the file went anywhere.

It was wrong, and I overruled it

Its first rollout plan had tools in pilot before anyone had designed them. I have run rollouts and it has not. I gave it the real sequence and it rebuilt the plan around mine.

What building it taught me

The same things the construction tools taught me. The rules matter more than the model. Most of the work was writing down how I want decisions made, and that is the same work as writing down how a reviewer checks a change order.

Keeping what a system knows apart from how it behaves, and both apart from where things stand, means each part can change without breaking the others.

A system told to disagree is more useful than one that agrees. That holds for a personal assistant and for a tool reviewing a pay application.

What this is and is not

It is a structured setup on Claude, using its projects, instructions, and memory. There is no code to publish. The documents themselves are personal, so this page describes the design and leaves the contents out.

It advises and drafts, and I decide.
